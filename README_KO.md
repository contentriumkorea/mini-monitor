# Mini Monitor

Mini Monitor는 OpenAI의 공식 제품이 아닌 독립 오픈소스 프로그램입니다. Windows PC의 CPU·GPU·RAM·VRAM과 공식 Codex 로그인으로 얻은 계정 한도를 3.5인치 USB 화면 또는 선택적 PC 상태창에 보여 줍니다. 가로 480×320과 세로 320×480 화면을 지원합니다. 실제 장치에 데이터를 보내는 동작은 사용자가 `모니터 시작`을 누른 뒤에만 시작됩니다.

![가로 대시보드 합성 미리보기](previews/native-refresh/normal.png)
![세로 대시보드 합성 미리보기](previews/native-refresh/normal_portrait.png)

위 이미지는 합성 수치를 사용한 미리보기입니다. 실계정 잔여 한도나 실제 USB 화면 사진이 아닙니다.

## 설치 및 첫 실행

1. [Releases](https://github.com/contentriumkorea/mini-monitor/releases)에서 최신 stable `Mini-Monitor.zip`을 받습니다. `Mini-Monitor` 폴더 전체를 원하는 위치에 압축 해제하세요. EXE만 따로 옮기면 실행되지 않습니다.
2. `Mini-Monitor.exe`를 실행합니다. 처음에는 설정창만 열리며 직렬 화면에 데이터를 전송하지 않습니다. Windows가 미서명 앱 경고를 표시할 수 있으니, 게시처와 [해시](https://github.com/contentriumkorea/mini-monitor/releases)를 직접 확인한 뒤 실행 여부를 결정하세요. 이 EXE는 Authenticode 코드 서명이 없습니다. 업데이트 메타데이터의 Ed25519 서명은 EXE 코드 서명과 다릅니다.
3. Codex 사용량과 크레딧을 보려면 설정창의 `ChatGPT로 로그인`에서 웹 브라우저 인증을 진행합니다. 공식 Codex app-server 실행 환경이 포함되어 별도 CLI 설치가 필요하지 않습니다. Mini Monitor는 다른 앱의 로그인 자료를 읽거나 복사하지 않고 앱 전용 `codex-home`을 사용합니다. 사용자 인증 정보는 배포본에 들어 있지 않습니다.
4. USB 화면을 사용하려면 화면 방향과 밝기를 확인한 다음 지원 USB 장치를 연결하고 `모니터 시작`을 누릅니다. 다른 프로그램이 같은 COM 포트를 사용 중이라면 먼저 해당 프로그램에서 포트를 닫으세요. PC에서만 보려면 `PC 상태창 켜기` 또는 `작업 표시줄 바 켜기`만 누르면 됩니다. 앱 실행 시 센서 수집을 별도로 시작해 설정창 미리보기에도 실시간 값을 표시하며, 이 수집은 USB 포트를 열거나 전송하지 않습니다. USB 모니터를 중지해도 PC 화면의 실시간 값은 계속 표시됩니다.

이 프로그램이 화면에 전송하는 장치는 USB VID `1A86`, PID `5722`, 일련번호 `USB35INCHIPSV2`가 모두 일치해야 합니다. 임의의 COM 포트를 지정해도 이 검증을 건너뛰지 않습니다. Windows 10/11 64비트, USB 직렬 드라이버, 센서 수집을 위한 .NET Framework 환경이 필요합니다.

## 화면과 계정 정보

설정창 상단의 `표시 제어`에서 미니 모니터, PC 오버레이, 작업표시줄 바를 함께 관리합니다. 밝기·방향·투명도 등 세부 설정은 아래 영역에 있고, 프로그램 종료 버튼은 하단에 고정됩니다.

`작업표시줄 바 설정`에서 CPU·RAM·GPU·VRAM·CODEX를 각각 선택하고 `아이콘`, `텍스트`, `아이콘+텍스트` 표시 방식을 고릅니다. 최소 한 항목이 필요하며, 선택한 항목만 표시합니다. 저장한 설정은 다음 실행에도 유지됩니다. 기본 작업표시줄의 알림 영역과 겹치는 위치는 왼쪽으로 조정됩니다.

Windows에서는 실제 주 작업표시줄과 알림 영역을 읽어 그 영역에 붙입니다. 모니터·해상도·배율·작업표시줄 위치가 바뀌면 표시 값이 같더라도 위치를 다시 계산합니다. `좌우 위치` 슬라이더는 알림 영역을 침범하지 않는 작업표시줄 범위를 0~100%로 표시합니다. 좌우 버튼은 1px씩 조정하며 `작업표시줄 복원`은 실제 작업표시줄 위치로 돌아갑니다. 세로 위치는 작업표시줄에 고정됩니다. 위치는 즉시 반영·저장되며, 항목 선택의 적용·취소와 별개입니다. 꺼져 있으면 위치만 저장하고 자동으로 켜지지 않습니다.

Windows 작업표시줄을 클릭해 바가 뒤로 가려지면 다음 UI 갱신에서 작업표시줄 바로 위의 창 순서로 복구합니다. 기존 팝업 메뉴 순서·키보드 포커스·위치·크기는 유지하며, Explorer 창 자체는 변경하지 않습니다. 작업표시줄 투명 프로그램은 필요하지 않습니다. 사용자가 끈 바는 자동으로 켜지지 않습니다.

설정창은 기본 약 960×720 크기로 열립니다. 기본 장치·Codex 정보를 간결하게 모으고, 업데이트는 별도 창에서 확인합니다. 로그인 실행 환경이 포함되어 `연결 문제 해결`, CLI 경로 선택·설치 안내 버튼은 제거했습니다. 로그인 오류는 계정 영역에 바로 표시됩니다. 작은 화면이나 높은 배율에서는 잘림을 막기 위해 내부 스크롤을 사용할 수 있습니다.

미니 모니터와 PC 오버레이의 각 카드는 제목 아래에 상세정보, 큰 퍼센트, 세로 게이지 순서로 표시합니다. CPU·GPU 이름은 줄바꿈으로 표시하고, 퍼센트 숫자는 게이지 옆에 크게 정렬합니다.

- CPU·RAM·GPU·VRAM·CODEX 다섯 카드가 화면 전환 없이 표시됩니다. 가로는 2+2+1 배치, 세로는 다섯 칸 세로 배치입니다. 각 카드 오른쪽 게이지가 아래에서 위로 채워지며, CPU·GPU 파형과 하단의 중복 바는 표시하지 않습니다. VRAM은 선택된 GPU의 전용 메모리 사용량/전체 용량 센서가 모두 유효할 때만 표시됩니다. 지원되지 않는 값은 추측하거나 0으로 만들지 않습니다.
- Codex 카드의 큰 숫자는 공식 계정 한도 중 가장 긴 유효 기간의 **남은 비율**입니다. 더 짧은 기간이 있으면 보조 수치로 표시합니다. 초기화 시각과 마지막 갱신 정보는 설정창에서 확인하세요. 한도 정보가 없거나 로그인 상태가 불분명하면 이전 계정 수치를 현재 값으로 보이지 않습니다.
- 설정창의 `로그아웃`은 확인 후 앱 전용 Codex 로그인만 종료합니다. 사용자의 일반 Codex 앱/CLI 로그인과 별개이며, 다른 데이터 원본으로 전환되지 않습니다.
- AI 정보는 Codex 계정 로그인으로만 조회합니다. 로컬 세션 기록·OpenAI API 조직 사용량·앱 활동 시간 수집은 더 이상 사용하지 않습니다. 이전 공급자 설정은 계정 로그인 방식으로 전환되며 기존 사용자 파일은 삭제하지 않습니다.
- 크레딧 잔액은 구독 사용 한도와 별도로 표시합니다. 응답에 잔액이 없으면 설정창에 `확인 불가`, 작은 화면에는 `--`로 표시하며, 실제 0과 구분합니다. 무제한은 서버에서 명시된 경우에만 표시합니다.
- 설정창은 블랙·그레이 색상으로 구성합니다. 작은 화면의 상태 배지 문구는 생략하고 VRAM 용량 숫자를 강조합니다. 로그인·오류 안내는 설정창에서 확인합니다.
- `작업 표시줄 바 켜기`는 CPU·RAM·GPU·VRAM·CODEX를 선택해 PNG 아이콘과 퍼센트로 표시하는 별도 소형 상태창입니다. 배경은 완전 투명하고 아이콘·숫자는 선명하게 유지됩니다. 작업 표시줄 자체를 수정하지 않고 실제 주 작업표시줄과 알림 영역 경계에 맞춰 붙습니다. 위치와 켜짐 상태는 저장됩니다. USB 모니터 시작 없이도 하드웨어 수치가 갱신됩니다. CODEX는 설정창과 같은 계정 데이터의 남은 한도를 표시합니다. 작업 표시줄 자동 숨김·전체 화면 앱·Windows 구성에 따른 가시성 차이는 있을 수 있습니다.
- PC 상태창은 크기 50–200%, 카드 면 불투명도 0–100%, 위치를 조정할 수 있습니다. Windows 자동 실행은 사용자가 체크한 경우에만 설정됩니다.

## 업데이트

0.2.8부터 업데이트의 신버전 정상 실행 확인이 끝나면 **구버전 백업과 완료된 업데이트 잔여 폴더를 자동으로 휴지통에 이동**합니다. 별도 정리 버튼은 없습니다. 기존 시작 메뉴·바탕화면 바로가기와 사용자가 이미 켜둔 자동 실행 경로도 정리 전에 새 프로그램으로 보정합니다. 자동 실행을 꺼둔 사용자는 임의로 켜지지 않습니다.

설정·로그인 데이터는 정리 대상이 아닙니다. 실패하거나 복구가 필요한 업데이트, 사용자 파일이 섞인 폴더, 해시가 달라진 파일, 출처를 확인할 수 없는 옛 폴더는 보존합니다. 교체 도구가 끝나기 전에는 정리하지 않으며, 잠금·권한 등의 이유로 정리하지 못한 완료 백업은 다음 정상 실행 때 다시 확인합니다. 휴지통 자체를 비우지는 않습니다.

**0.2.7 이전 버전의 업데이트 오류:** 이전 앱에 포함된 업데이터는 사용 중인 파일을 이동하다가 프로그램 폴더가 일부만 이동할 수 있습니다. 새 배포본만으로 이미 실행 중인 구형 업데이터를 바꿀 수 없으므로, 0.2.6 이하에서는 앱 내 업데이트를 반복하지 말고 프로그램을 종료한 뒤 0.2.7 이상의 ZIP 전체를 새 폴더에 압축 해제해 실행하세요. 기존 프로그램·백업 폴더와 `%LOCALAPPDATA%\AI-Mini-Monitor` 설정·로그인 데이터는 삭제하지 마세요. 새 폴더에서도 기존 앱 전용 설정·로그인을 사용합니다. 바로가기나 자동 실행 경로가 이전 위치를 가리키면 새 실행 위치로 변경해야 합니다.

0.2.7의 업데이터는 같은 볼륨의 폴더 이름을 원자적으로 변경합니다. 파일 잠금으로 교체할 수 없으면 기존 프로그램을 그대로 보존하며, 복구에 실패한 경우 복구 완료로 기록하지 않습니다. 다운로드·서명 검증과 설치·재실행 검증은 별개입니다.

0.2.7부터 서명된 업데이트 파일은 `update-v2-manifest.json` / `update-v2-manifest.sig` 이름만 사용합니다. 구형 앱에는 새 버전 알림과 수동 다운로드 안내가 표시되지만 위험한 자동 교체는 제공되지 않습니다. 배포 시 구형 이름의 업데이트 파일을 함께 올리면 이 보호가 해제되므로 구형 이름 별칭을 게시하지 않습니다. 구형 업데이트가 이미 준비되어 있더라도 적용·재시도하지 말고, 교체를 시작하기 전에 앱을 종료하고 수동 설치하세요. 새 배포가 이미 시작한 구형 교체 도구를 중단시키지는 않습니다.

앱은 시작할 때와 실행 중 주기적으로 GitHub의 stable Release를 확인합니다. 네트워크 확인은 기본적으로 24시간 간격으로 제한되며, 설정창의 `업데이트 확인` 버튼으로 즉시 다시 확인할 수 있습니다. 새 버전은 알림만 표시하며 다운로드나 설치를 자동 실행하지 않습니다. 사용자가 `업데이트 후 다시 시작`을 눌러야 서명·해시 검증 후 교체가 시작됩니다. 서명이 없거나 설치 폴더에 사용자 파일/수정 파일이 있으면 자동 교체를 거부하고 수동 설치를 안내합니다. 사용자 데이터 폴더와 기존 프로그램 폴더를 임의로 삭제하지 않습니다.

이 기능이 없는 옛 `AI-Mini-Monitor` 배포본과 공개를 철회한 `0.2.0` 빌드도 **0.2.7 이상의 최신 버전으로 바로 수동 업그레이드**해야 합니다. `0.2.0`은 앱 내에서 이번 업데이트를 발견하지 못합니다. 기존 실행 프로그램이 켜져 있다면 먼저 정상 종료한 뒤 새 `Mini-Monitor` 폴더를 별도 위치에 압축 해제해 실행하세요. 기존 `%LOCALAPPDATA%\AI-Mini-Monitor` 사용자 데이터와 이전 프로그램 폴더는 보존됩니다. 0.2.7 이상에서는 이후 v2 업데이트 경로를 사용할 수 있습니다.

## CLI와 안전한 확인

배포 폴더에서 `Mini-Monitor-CLI.exe`는 콘솔용입니다. 다음 명령은 진단 또는 합성 미리보기이며 USB 직렬 포트를 열어 화면에 쓰지 않습니다.

```powershell
.\Mini-Monitor-CLI.exe --version
.\Mini-Monitor-CLI.exe --diagnose -
.\Mini-Monitor-CLI.exe --render-previews .\previews-generated
```

`--diagnose`에는 장치 및 센서의 비밀이 아닌 정보가 포함될 수 있으므로 공개 게시 전 내용을 검토하세요. `--desktop-smoke`는 자동 검증 전용이며 반드시 `--no-serial`과 함께 사용합니다. 실계정 로그인과 물리 USB 전송은 사용자 환경에서 별도 검증이 필요합니다.
