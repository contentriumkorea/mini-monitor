# 작업표시줄 바 네이티브 창 전환 설계

## 목적과 승인된 범위

4K 노트북의 Windows 배율 환경에서 작업표시줄 바가 작거나 잘못 배치되는 문제와, 전체화면 영상·게임 위에 표시가 남는 문제를 해결한다. 사용자는 작업표시줄 바만 Windows 네이티브 창으로 전환하고 검증 후 배포하는 방향을 승인했다. 이 문서는 그 방향의 구체적인 구현 경계와 배포 기준을 정의하며, 문서 승인 후 구현 계획을 작성한다.

설정창, PC 오버레이, USB 미니 모니터, 계정 로그인과 사용량 수집 방식은 유지한다. 다른 Codex 앱의 로컬 사용량·인증 자료를 읽지 않는다. 기존 사용자 설정·앱 전용 로그인·자동 실행 상태를 보존한다. 제조사 원본 `35inchENG`는 변경하거나 실행하지 않는다.

## 원인과 선택한 접근

현재 바는 `OverlayWindow`를 상속한 Tk Toplevel이다. 실제 Windows 창 검증에서 Tk의 창 생성·표시 단계가 HWND를 교체하거나 포커스를 가져오는 동작을 확인했다. 포커스 검증은 아직 실패하고 있으며 새 배포본은 공개하지 않았다.

선택한 접근은 **작업표시줄 바만 자체 Win32 HWND를 소유**하는 것이다. Tk 창에 비활성 표시 설정을 추가하는 방식은 사용하지 않는다. 설정창의 Tk 이벤트 루프는 유지하되, 바의 생성·그리기·표시·숨김·마우스 처리는 Win32 창에서 담당한다. Explorer에 삽입하거나 DLL을 주입하지 않고, 작업표시줄의 경계와 표시 상태를 읽어서 연동한다.

## 창과 수명

- 새 `ui/native_taskbar.py`에 바 전용 창을 구현한다. UI 스레드에서 생성·갱신·폐기하며 별도의 GUI 스레드나 전역 마우스 훅은 추가하지 않는다.
- 창은 `WS_EX_LAYERED | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`와 `WS_POPUP`으로 생성한다. 표시·복귀는 `SW_SHOWNOACTIVATE`와 비활성 창 배치 호출을 사용한다. `WM_MOUSEACTIVATE`는 활성화를 막는다.
- WNDPROC 콜백은 HWND의 전체 수명 동안 강한 참조를 유지한다. 64비트 HWND·WPARAM·LPARAM·LRESULT 자료형을 정확하게 선언한다. 생성 중 실패한 창·핸들은 회수하고, 종료 후 메시지가 폐기된 객체를 참조하지 않게 한다.
- 기존 `LayeredWindowPresenter`의 RGBA 업로드를 안정적인 네이티브 HWND 어댑터를 통해 재사용한다. PC 오버레이용 Tk presenter에는 바 전용 표시 동작을 추가하지 않는다. 이전 턴에서 작성한 미배포 Tk 비활성 표시 실험은 관련 부분만 제거한다.

## DPI와 배치

- 실행 파일의 기존 PerMonitorV2 DPI 선언을 유지한다. 바·알림 영역·모니터 경계·그림 크기는 같은 화면 픽셀 기준으로 처리한다.
- 실제 주 작업표시줄 창의 DPI를 읽는다. 100·150·200·250% 및 실행 중 배율·해상도·주 모니터 변경을 지원한다.
- `render_taskbar_frame`은 기본 100% 호출과 호환되도록 DPI 입력을 추가하고, 글꼴·아이콘·여백을 해당 DPI에서 직접 그린다. 4K에서는 작은 완성 이미지를 늘리는 것에만 의존하지 않는다.
- 세로 위치는 작업표시줄 내부 중앙에 고정하고, 가로 위치는 알림 영역 왼쪽의 유효 범위 안으로 제한한다. 기존 슬라이더·한 픽셀 이동·위치 초기화·드래그를 유지한다.
- 환경이 바뀌면 마지막 유효 범위에서의 상대 가로 위치를 새 범위로 옮긴다. 작업표시줄을 찾지 못하거나 선택한 항목을 표시할 폭·높이가 부족하면 바를 숨긴다. 앱 화면 위나 작업표시줄 위쪽으로 떠오르는 대체 배치는 사용하지 않는다.

## 표시 상태

- 사용자의 ON/OFF와 실제 창의 표시 상태를 분리한다. 전체화면·자동 숨김으로 잠시 숨겨진 경우에는 저장된 ON 설정을 OFF로 바꾸지 않는다.
- 바가 있는 모니터를 덮는 전경 앱의 실제 클라이언트 영역을 이용해 전체화면을 판별한다. 일반 최대화 창과 바탕화면은 전체화면 영상으로 오인하지 않는다. 다른 모니터의 전체화면은 주 작업표시줄 바를 불필요하게 숨기지 않는다.
- 전체화면, 작업표시줄 자동 숨김, Explorer 재시작, 유효한 작업표시줄 영역 부재 중에는 표시하지 않으며 최상단 순서를 복구하려고 창을 올리지 않는다.
- 조건이 해제되면 최근 수치로 자동 복귀한다. 숨겨진 동안 수집과 캐시 갱신은 계속한다. 사용자가 OFF로 바꿨다면 자동 복귀하지 않는다.
- 처음 켤 때와 숨김 후 복귀할 때 모두 기존 전경 창의 포커스를 유지해야 한다. 이 실제 Windows 검증이 배포의 필수 조건이다.

## 입력과 기존 기능 호환

- 바 내부 드래그는 자체 창의 마우스 메시지와 마우스 캡처로 처리한다. 이동은 가로 유효 범위를 벗어나지 않으며 세로는 작업표시줄 내부에 유지한다. 캡처 해제·취소·창 폐기에서 드래그 상태를 정리한다.
- `TaskbarWindow`의 기존 애플리케이션용 인터페이스를 유지한다: `state`, `visible`, `closed`, `show`, `hide`, `destroy`, `update_sensor`, `set_options`, `set_position`, `horizontal_position`, `set_horizontal_percent`, `nudge_horizontal`, `reset_horizontal_position`.
- 상태 콜백은 기존 `OverlayState` 형식으로 전달해 설정 저장 코드를 유지한다. `visible`은 사용자의 켜짐 의도를 의미한다. Tk 창 자체를 반환하는 내부 테스트는 네이티브 표시 상태 검증으로 전환한다.
- CPU·RAM·GPU·VRAM·Codex 항목 선택, 아이콘/텍스트 표시, 투명 배경과 불투명 글자, 축약 없는 크레딧, 한도 소진 시 잔액이 있을 때만 Credit 표시하는 규칙을 유지한다.
- 네이티브 창 생성·렌더링 실패는 바 기능의 오류로만 보고하며 전체 앱·USB 모니터·계정 로그인 기능을 종료하지 않는다.

## 검증과 배포 기준

1. 테스트 우선으로 창 생성·폐기, DPI별 그림과 배치, 전체화면/최대화/다른 모니터 판별, 자동 숨김·Explorer 복구, 공간 부족, 드래그 범위, ON/OFF 저장, 최신 수치 복귀를 검증한다.
2. 격리된 실제 Windows 창 테스트에서 초기 표시·숨김·복귀 동안 `GetForegroundWindow`가 유지되는지 확인하고, HWND 교체나 GDI/콜백 수명 오류가 없는지 확인한다. 사용자 앱이나 Explorer를 변경하는 테스트는 하지 않는다.
3. 전체 테스트와 별도 코드 검토가 통과한 후 Windows 실행 파일을 빌드한다. 빌드된 실행 파일의 DPI 선언·창 실행·종료·업데이트·실패 시 복구를 확인한다.
4. 새 안정 버전 0.2.10으로 서명된 `Mini-Monitor.zip`, `update-v2-manifest.json`, `update-v2-manifest.sig`만 GitHub에 배포한다. 기존 0.2.9에서 새 버전 감지와 공개 파일 검증을 확인한다. 구형 업데이터 보호와 원자적 교체·복구·구버전 자동 정리 기능은 유지한다.
5. 특정 노트북의 물리적인 화면·배율과 모든 게임을 이 PC 테스트로 검증했다고 주장하지 않는다. 자동 테스트, 실제 네이티브 창 검증, 노트북 사용자 확인을 구분해 보고한다. 이번 요청에 없는 이 PC의 설치·자동 실행 설정 변경은 별도로 수행하지 않는다.

## 구현하지 않는 항목

Explorer 확장/DeskBand 등록, Explorer 재시작·변경, 다른 앱에 창 삽입, Windows 배율 설정 변경, UI 전체 재작성, 신규 라이브러리·별도 CLI 의존성, 다른 앱의 로컬 사용량 수집은 범위에서 제외한다.
