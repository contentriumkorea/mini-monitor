# Mini Monitor 경량 온라인 설치기 설계

상태: 사용자 승인 후 구현·검증 진행 중. 실제 사용자 설치본은 변경하지 않는다.

## 목적

사용자는 작은 설치 EXE 하나를 보관하고, 언제 실행하든 최신 정식 Mini Monitor를 설치한다. 앱의 새 버전을 배포할 때 설치 EXE를 다시 만들거나 사용자에게 다시 받도록 요구하지 않는다. 설치기 자체의 보안·Windows 호환성 변경은 별도 유지보수로 취급한다.

## 확인한 현재 배포

- GitHub 최신 정식 릴리스는 v0.2.10이며 draft/prerelease가 아니다.
- Mini-Monitor-Setup.exe: 133,186,560 bytes. 0.2.10 ZIP을 내장한 오프라인 설치기다.
- Mini-Monitor.zip: 133,088,142 bytes. 기존 앱 업데이트용 전체 패키지다.
- update-v2-manifest.json 및 update-v2-manifest.sig가 공개되어 있다.
- 설치기 배포 워크플로는 성공했다. 공개 메타데이터를 이용한 0.2.9의 0.2.10 감지, 알림 대기, 서명·해시 검증도 통과했다.

## 분리할 배포 구성

| 구분 | 배포 위치 | 갱신 조건 |
|---|---|---|
| 온라인 설치기 | installer-v1 전용 릴리스의 Mini-Monitor-Setup.exe | 설치 엔진 보안·호환성 변경 때만 |
| 실제 프로그램 | vX.Y.Z 앱 릴리스의 Mini-Monitor.zip | 앱 버전 갱신 때 |
| 버전·다운로드·해시 목록 및 서명 | 같은 앱 릴리스의 update-v2-manifest.json / .sig | 앱 패키지와 함께 |

설치기 전용 릴리스는 Latest로 지정하지 않는다. 기존 앱과 설치기의 Latest 조회는 정식 앱 릴리스를 가리켜야 한다. 다운로드 첫 화면은 고정된 설치기 링크를 사용하며, ZIP은 별도의 포터블/업데이트 파일 안내에 둔다. 기존 0.2.10 오프라인 설치기는 과거 배포 기록으로 보존하고 경량 설치기로 표시하지 않는다.

## 설치 동작

1. 설치 EXE 실행 후 사용자가 설치를 선택한다. EXE에는 실제 프로그램을 포함하지 않는다.
2. 고정된 공식 저장소에서 최신 정식 앱 릴리스 정보를 조회한다. 임의의 다운로드 주소를 사용자 입력으로 받지 않는다.
3. 기존 공개키로 manifest의 Ed25519 서명을 검증한다. 저장소·버전·자산 URL·크기·스키마도 확인하며, 서명되지 않은 파일로 대체하지 않는다.
4. 서명된 목록의 프로그램 ZIP을 임시 위치에 내려받는다. 다운로드 진행률과 오류/재시도 안내를 표시한다. HTTPS와 허용된 GitHub 자산 호스트만 사용하고 다운로드/압축해제 크기·경로 제한을 적용한다.
5. ZIP 해시 및 압축 해제한 파일 목록을 검증한 후에만 기존 설치를 교체한다. 다운로드/검증 실패와 취소는 기존 프로그램을 바꾸지 않는다.
6. 기존 사용자별 설치 위치, 시작 메뉴, 선택적 바탕화면 바로가기, 제거 등록을 유지한다. 표시 버전은 설치기 버전이 아니라 실제 내려받은 앱 버전이다.
7. 기존 업데이트 작업과 같은 잠금을 사용하고, 실행 중인 대상 앱은 사용자가 종료하도록 안내한다. 낮은 버전 덮어쓰기는 거부한다.
8. 교체·등록 실패 시 이전 프로그램과 등록 정보를 복구한다. 로그인·설정·자동 실행 선택과 알 수 없는 사용자 파일은 보존한다.

## 설치기 크기와 유지보수

기존 .NET Framework 기반 설치 마법사를 재사용한다. 앱 ZIP 및 Python/Codex 런타임을 내장하지 않는다. 공개키와 검토된 Ed25519 검증 구성요소, 작은 제거 도구만 포함한다. 설치 EXE는 1 MB 이하를 목표로 하며 실제 빌드 크기로 확인한다. 암호 검증 알고리즘을 직접 새로 구현하지 않는다.

이 방식은 설치파일의 다운로드 용량을 줄이며, 설치 중 받는 앱의 실제 용량까지 줄이지는 않는다. 인터넷 연결이 필요하다. 설치기 고정 배포는 앱 버전마다 재빌드하지 않는다는 뜻이며, 보안 취약점이나 향후 Windows/서명 규격 변화까지 영구적으로 업데이트하지 않는다는 약속은 아니다.

## 기존 앱 업데이트

기존 앱은 계속 서명된 v2 목록과 프로그램 ZIP을 사용한다. 온라인 설치기를 다시 다운로드하거나 실행시키지 않는다. 기존 원자적 교체·실패 복구 정책을 유지하며, 레거시 update-manifest 이름 별칭을 추가하지 않는다. 설치기 전용 릴리스 때문에 업데이트 조회가 잘못되거나 알림이 생기지 않도록 검증한다.

## 완료 기준

- 동일한 설치 EXE로 서로 다른 두 정식 버전 테스트 피드를 설치하고, EXE 해시는 바뀌지 않는다.
- 실제 공개 앱 패키지의 다운로드·서명·해시·설치를 격리된 경로에서 검증한다.
- 잘못된 서명·해시·외부 URL·과대 파일·경로 탈출·중단된 다운로드는 기존 설치를 보존한다.
- 설치 취소·잠금 충돌·재설치·실행 실패 복구·제거 및 설정 보존을 검증한다.
- 고정 설치기 다운로드와 앱 Latest 릴리스를 각각 확인한다. 기존 0.2.9의 업데이트 감지와 현재 버전의 중복 알림 억제를 확인한다.
- GitHub 첫 화면에는 경량 설치기를 우선 표시하고, 포터블 파일과 업데이트용 메타데이터를 구분한다.
