# Mini Monitor 설계서

- 작성일: 2026-10-03
- 상태: 2026-10-03 사용자 승인 완료. 설계·구현 계획에 따라 병렬 구현, 검토, 검증 및 공개 GitHub 배포를 진행한다.
- 단계: 승인된 구현 계약. 실제 완료 여부와 검증 결과는 TEST_RESULTS.md 및 공개 Release의 검증 내역으로 구분한다.
- 검증 범위: 기존 소스·미리보기·공식 인터페이스에 근거한 설계이며, 실제 계정 로그인·실시간 한도·USB 장치 전송은 아직 검증하지 않았다.
- 작업 경계: `AI-Mini-Monitor` 프로젝트만 대상이다. 형제 폴더 `35inchENG`, 기존 배포본 및 실제 COM 장치는 이 설계 작업에서 건드리지 않는다.

## 1. 목적과 범위

3.5인치 화면에서 CPU·GPU·RAM·Codex 상태를 빠르게 읽고, GPU 전용 VRAM과 로그인 계정의 실제 Codex 한도를 확인할 수 있는 Windows 프로그램으로 개선한다. 사용자에게 보이는 제품명은 `Mini Monitor`로 통일한다.

- 포함: 네 카드의 가독성 개선, 전용 VRAM 사용량·전체 용량, 지원 시 GPU 전력, 공식 Codex 로그인, 설정창 정리, 이름 변경, 검증된 소스·Windows 배포본 공개, 향후 업데이트 알림·간편 적용.
- 제외: 추가 GPU 클럭·팬 상세 UI, GPU 선택 화면, 임의 대시보드 편집기, 계정 다중 관리, 클라우드 서비스, 디스크·네트워크·날씨·볼륨 수집, USB 프로토콜 재설계.
- 구현 기반은 기존 Python·Pillow·Tk·LibreHardwareMonitor이다. UI 프레임워크 전환이나 광범위한 리팩터링을 하지 않는다.
- GPU 확대 비대칭 배치와 순환 페이지 대신 균형 잡힌 네 카드로 확정한다. VRAM과 Codex 주 한도가 화면 전환 없이 항상 같은 위치에 있어야 한다.

## 2. 네이티브 화면과 정보 위계

좌표는 `(x, y, width, height)`이며 모든 사각형은 서로 겹치지 않는 반개구간이다.

| 화면 | 상태 표시줄 | CPU | GPU | RAM | CODEX |
|---|---|---|---|---|---|
| 480×320 | `(8,8,464,20)` | `(8,36,228,134)` | `(244,36,228,134)` | `(8,178,228,134)` | `(244,178,228,134)` |
| 320×480 | `(8,8,304,20)` | `(8,36,304,103)` | `(8,147,304,103)` | `(8,258,304,103)` | `(8,369,304,103)` |

- 세로 화면은 320×480 좌표에 직접 렌더링한다. 가로 이미지를 회전해 글자를 세우지 않는다.
- `CPU`, `GPU`, `RAM`, `CODEX` 제목은 모두 18px 이상 ExtraBold로 유지한다. 기존 사용자가 요구한 큰 제목을 축소하지 않는다.
- 주요 퍼센트 숫자는 가로 42px, 세로 40px ExtraBold의 고정 폭 숫자를 사용한다. `%`는 각각 21px·20px이며 실제 글리프 밑면을 숫자 밑면에 맞춘다.
- 각 카드의 주 수치에는 0–100% 가로 게이지를 유지한다. 가로 화면은 10px 이상, 세로 화면은 8px 이상 높이로 확보하고, 작은 스파크라인과 구분하여 숫자 다음으로 쉽게 읽히게 한다. 게이지·VRAM·보조 한도가 서로 겹치지 않는 별도 영역을 갖는다.
- 네 주요 값의 오른쪽 그룹 앵커는 `card.x + 112`, 기준선은 가로 `card.y + 80`, 세로 `card.y + 73`으로 통일한다. 0·9·99·100에서 앵커가 이동하지 않는다.
- 의미 있는 보조 수치는 12–13px를 목표로 한다. 모델명·갱신 시각 같은 보조 식별 정보만 10–11px를 허용하며 긴 모델명은 말줄임한다.
- 제목은 좌측, 큰 값은 좌측 수치 영역, 온도·용량·한도 라벨은 우측 정보 영역에 둔다. 공간 부족을 큰 숫자·제목 축소로 해결하지 않는다.
- 작은 CPU·GPU·RAM 스파크라인은 카드 하단의 보조 정보로 유지한다. 큰 그래프·장식 격자·제목 밑줄·강한 세로 레일·반복 `NORMAL` 라벨을 제거한다.
- 차분한 짙은 회색 바탕, 8px 둥근 모서리, 은은한 1px 경계를 사용한다. 주요 글자는 흰색이며 색상은 작은 구분 표식과 그래프에 제한한다.
- 상태 표시줄은 제품과 연결 상태만 간결하게 보여 준다. 미리보기·데모를 실제 연결 상태로 오인시키지 않는다.

| 카드 | 큰 값 | 항상 보이는 보조 정보 | 생략 가능한 정보 |
|---|---|---|---|
| CPU | 사용률 | 코어/패키지 온도, 짧은 모델명 | 정상 상태 설명 |
| GPU | 사용률 | 코어 온도, 짧은 모델명, `VRAM 사용 / 전체 GiB` | 센서가 없는 전력 |
| RAM | 사용률 | 사용 / 전체 GiB, 남은 용량 | 반복되는 사용률 설명 |
| CODEX | 최장 유효 한도의 남은 비율 | 실제 창 길이 라벨, 짧은 한도 비율, 연결/지연 상태 | 작은 카드의 5H 초기화 시각 |

Codex의 통상 7D 창은 큰 값, 5H 창은 보조 값이라는 기존 위계를 유지한다. 응답의 창 길이가 다르면 실제 길이로 라벨을 만들며, 초기화 시각 등 전체 정보는 설정창에서 제공한다.

## 3. GPU 데이터 계약

- `SensorSnapshot`과 `DisplaySnapshot`에 `gpu_vram_used_gib: Metric`, `gpu_vram_total_gib: Metric`, `gpu_power_w: Metric`를 추가한다. 기본값은 이유가 있는 미지원 값이며 기존 생성자를 깨뜨리지 않는다.
- `SensorReading` 끝에 `hardware_identifier: str | None = None`을 추가하고 LibreHardwareMonitor의 `hardware.Identifier`로 채운다.
- 샘플마다 하나의 비가상 물리 GPU를 결정하고 모델·사용률·온도·VRAM·전력을 동일한 하드웨어 식별자에 묶는다. 유효한 전용 용량과 코어 센서가 있는 외장 GPU를 우선하며 순서는 결정적이어야 한다.
- 기존 설정에서 찾을 수 있는 GPU 사용률 센서, 다음으로 온도 센서 순서로 어댑터를 결정하고 그 안에서 설정을 존중한다. 충돌하는 다른 어댑터의 센서는 해당 항목만 미지원과 이유로 반환하며, 전체 카드가 다른 GPU로 옮겨 가거나 어댑터 수치를 혼합하지 않는다.
- LibreHardwareMonitor의 정확한 `GPU Memory Used` / `GPU Memory Total` 쌍을 우선한다. `SmallData`의 MiB는 1024로 나누어 GiB로 변환한다.
- 그 쌍이 없으면 같은 GPU의 대응하는 D3D Dedicated Used/Total 쌍만 대체할 수 있다. 서로 다른 센서 계열의 사용량·전체 용량을 섞지 않는다.
- 공유 메모리, 메모리 컨트롤러 부하율, 버스 부하율을 전용 VRAM 용량·점유율로 표시하지 않는다. 누락된 전체 용량을 다른 값에서 추정하지 않는다.
- 전력은 같은 GPU의 `GPU Package` Power(W)가 제공될 때만 표시한다. 없으면 공간을 비우며 0 W를 만들지 않는다.
- 값의 유한성·음수·전체 용량 0 이하를 검증한다. 유효한 사용량·전체 용량 쌍이 없으면 VRAM 줄은 `-- / -- GiB`이다. 미지원 이유는 진단 데이터에만 남긴다.
- 기존 단일 센서 수집 스레드와 샘플 주기를 유지한다. VRAM·전력 때문에 별도 GPU 폴러를 만들지 않는다.

## 4. Codex 공식 계정 연결

### 실행과 자격 증명

- 새 공급자 키는 `codex_account`이며 기본 추천 항목이다. 기존 `codex_local`, `openai_api`, `chatgpt_activity`, `not_configured` 키는 호환 유지한다.
- 공식 Codex CLI의 로컬 `app-server` 표준 입출력 JSON-RPC를 사용한다. 브라우저 화면 스크래핑, 비공개 HTTP API, 세션 내용 추정, 토큰 파일 직접 읽기는 금지한다.
- 앱 전용 홈은 `user_data_dir() / "codex-home"`이다. 자식 프로세스에만 이 `CODEX_HOME`과 공식 파일 자격 증명 저장 방식을 지정하며 기본 `~/.codex` 인증을 공유·복사하지 않는다.
- 자식 프로세스의 작업 디렉터리도 앱 전용 홈으로 고정한다. 상위 프로세스의 API 키·인증 토큰 환경 변수를 전달하지 않아 다른 계정이나 작업 폴더 설정이 계정 연결에 개입하지 않게 한다.
- Mini Monitor는 `auth.json`이나 토큰을 열거나 출력하지 않는다. 공식 CLI가 해당 격리 디렉터리에서 로그인 저장·갱신·삭제를 담당한다.
- 설치된 CLI 또는 사용자가 지정한 경로를 발견하고 실제 Windows 실행 파일의 유효한 OpenAI 서명과 app-server 지원을 확인한다. 셸 문자열 결합 없이 인수 배열로 실행한다.
- CLI가 없거나 검증에 실패하면 `Codex CLI 설치 안내`와 `설치된 CLI 찾기`를 제공한다. 자동 설치하거나 Codex 데스크톱 내부의 비공개 실행 파일을 복사·번들하지 않는다.
- 첫 실행은 `initialize` 요청의 성공 응답 후 `initialized` 알림을 보내고 진행한다. 허용 작업은 `account/read`, `account/login/start`, `account/login/cancel`, `account/logout`, `account/rateLimits/read`와 해당 계정 알림 처리이다.
- 로그인 시작은 `type: "chatgpt"`이며, HTTPS·userinfo 없음·정확한 호스트 `chatgpt.com` 또는 `auth.openai.com`을 검증한 URL만 기본 브라우저로 연다. 쿼리 문자열은 표시·로그에 남기지 않는다. 다른 호스트는 열지 않고 업데이트 필요를 알리며 로그인 대기에는 취소 동작을 제공한다.
- `account/login/completed`, `account/updated` 수신 후 계정을 다시 읽고 한도를 갱신한다. 일반 계정 확인은 `account/read`의 `refreshToken: false`를 사용한다.
- 모델 작업·새 대화·턴 생성·사용량 초기화·크레딧 구매는 호출하지 않는다. API 키 계정은 ChatGPT 구독 한도로 표시하지 않는다.

### 단일 소유와 UI 경계

- `app.py`가 앱 수명 단위 `CodexAccountService` 하나를 소유한다. 서비스 객체는 앱 시작 때 만들고 자식 프로세스는 필요한 계정 작업 시 지연 시작한다.
- 서비스는 하나의 app-server 프로세스와 JSON-RPC 읽기 루프를 소유하고 요청 ID로 응답을 연결한다. 로그인·취소·갱신·로그아웃 요청은 직렬화한다.
- 계정 상태는 불변 스냅샷으로 게시한다. Tk는 메인 스레드에서만 화면을 갱신하며 프로세스·네트워크 응답을 기다리지 않는다.
- 설정창 로그인·취소·계정 확인·수동 갱신은 모니터 시작, 센서 수집, USB 장치 검색 없이 동작한다.
- `MonitorController`는 같은 서비스의 최신 상태만 읽는다. 모니터 시작·중지 때 별도 app-server를 생성하거나 로그인 진행을 끊지 않는다.
- 자동 조회는 모니터 실행 중 기본 60초 간격이다. 중지는 주기 조회만 멈추며, 설정창의 수동 갱신과 로그인 완료 직후 조회는 계속 가능하다.
- `account/rateLimits/updated`는 부분 알림일 수 있으므로 전체 조회의 계기로만 사용한다. 동일 로그인 세대에서 `account/rateLimits/read` 전체 응답을 확인한 뒤 스냅샷을 교체하며, 중복 요청을 합치고 오류 재시도는 간격을 늘려 최대 5분까지 제한한다.
- 앱 종료 시 대기 로그인을 취소하고 읽기 루프·자식 프로세스를 제한 시간 안에 닫는다. 종료되지 않으면 자신이 시작한 자식만 정리하며 다른 Codex 프로세스를 종료하지 않는다.

### 한도 선택과 표시

- `rateLimitsByLimitId["codex"]`를 우선한다. 없으면 `rateLimits.limitId`가 명시적으로 `codex`일 때만 레거시 응답을 사용한다.
- 이름 있는 모델 전용 버킷은 합산·병합·대체하지 않는다. canonical Codex 버킷이 없으면 `한도 정보 없음`이다.
- 각 창의 유한한 `usedPercent`, 유효한 `windowDurationMins`, 선택적 초기화 시각을 검증한다. 사용률은 0–100 범위에서 검증하고 남은 비율은 `100 - usedPercent`로 계산한다.
- 누락·null·잘못된 수치는 미상이다. 0% 사용이나 100% 남음으로 바꾸지 않는다. 무제한은 서버가 명시한 경우에만 별도로 표현한다.
- 유효한 창 중 가장 긴 창을 주 값으로, 다음 짧은 창을 보조 값으로 선택한다. 한 창만 유효하면 그 창만 보여 주고 짧은 창을 만들어 내지 않는다.
- `windowDurationMins`로 `7D`, `5H` 등의 라벨을 만든다. 새로운 길이도 실제 단위로 표시하며 모델명이나 구독명으로 창 길이를 추측하지 않는다.
- 작은 카드에 5H 초기화 시각을 추가하지 않는다. 설정창에는 각 창의 남은 비율·초기화 시각·마지막 성공 갱신을 제공한다.
- 남은 비율과 사용 비율은 라벨로 구분한다. 게이지가 사용 비율을 쓰는 경우 `USED`, 남은 비율이면 `LEFT`를 명시한다.

### 오류·계정 전환

| 상황 | 상태와 수치 처리 | 사용자 동작 |
|---|---|---|
| CLI 없음·검증 실패 | 설정 필요, 수치 없음 | 설치 안내 또는 경로 선택 |
| 미로그인·인증 만료 | 로그인 필요, 이전 계정 값 즉시 제거 | 로그인 |
| 로그인 진행·취소 | 대기/취소 상태, 성공으로 표시하지 않음 | 취소 또는 재시도 |
| 네트워크·시간 초과 | 같은 계정의 마지막 값만 `지연`과 성공 시각을 붙여 보존 | 새로고침 |
| 버킷·창 누락 또는 형식 오류 | 해당 수치 미상, 오류를 100% 남음으로 해석하지 않음 | 재조회 |
| 로그아웃·계정 변경 | 캐시·한도·계정 표시 즉시 제거, 새 계정 확인 후에만 게시 | 명시적 로그아웃/계정 변경 |

마지막 성공 이후 두 갱신 주기(기본 120초)를 넘긴 값은 정상 실시간 상태로 표시하지 않는다. 로그인 세대가 바뀌면 이전 세대의 늦은 응답도 폐기한다. 초기화 시각이 지나도 새 응답 없이 잔여량을 100%로 복원하지 않는다.

## 5. 설정창과 기존 동작 보존

- 기존 좌측 설정·우측 미리보기 구조를 간결하게 정돈한다. `Mini Monitor` 제목, 실행 상태, 연결, Codex 계정, 핵심 동작을 먼저 보이게 한다.
- 한국어 본문은 11–12pt를 목표로 하며 장황한 기술 설명은 고급 영역으로 옮긴다. 작은 작업 영역·고배율 DPI에서는 기존 스크롤과 창 맞춤을 유지한다.
- 계정 영역은 `ChatGPT로 로그인`, 로그인 대기/취소, 연결 계정·플랜, `새로고침`, `연결 해제`, 명시적 `로그아웃` 상태를 구분한다. 이메일은 설정창에만 표시하고 대시보드·진단·공개 캡처에는 넣지 않는다.
- `연결 해제`는 Mini Monitor의 조회만 중단한다. `로그아웃`은 확인 후 격리 홈의 공식 로그아웃을 호출한다. 둘 다 기본 Codex 앱·CLI 계정에는 영향을 주지 않는다.
- 기존 로컬 읽기는 `로컬 기록 · 실시간 아님`으로 고급 영역에 남기며 기존 동의 절차를 유지한다. 로그인 공급자 실패 시 자동으로 전환하지 않는다.
- OpenAI 조직 Usage/Costs와 앱 활동 시간은 명시적으로 구분된 기존 고급 대안이다. ChatGPT 구독 사용량과 섞지 않는다.
- USB 식별·직렬 전송·최신 프레임 우선·전원 이벤트 처리는 유지한다. 밝기 1–50, 가로/세로와 180° 반전, 자동 실행, 재연결을 훼손하지 않는다.
- PC 상태창은 항상 위·전체 드래그·위치 복원·크기 설정을 유지한다. 카드 배경만 0–100% 불투명도를 적용하고 글자·수치·게이지·그래프는 불투명하게 유지한다.
- 오버레이의 카드 바깥은 투명하고 격자를 표시하지 않는다. Win32 hit-test 보호와 다중 모니터 음수 좌표 처리를 보존한다.

## 6. 이름 변경과 호환성

- UI 제목·트레이·안내·README의 제품명은 `Mini Monitor`이다. 배포 실행 파일은 `Mini-Monitor.exe`, `Mini-Monitor-CLI.exe`, 배포 폴더는 `Mini-Monitor`이다.
- Python 내부 패키지 `ai_mini_monitor`, 기존 사용자 데이터 디렉터리 `AI-Mini-Monitor`, 단일 인스턴스 mutex는 유지한다. 이름 정리 때문에 설정·DPAPI 자료를 이동하거나 중복 실행 보호를 끊지 않는다.
- 기존 CLI 진입점은 호환 별칭으로 유지할 수 있다. 빌드·실행·진단 스크립트와 패키징 테스트는 새 배포 이름을 일관되게 참조한다.
- 자동 실행은 해당 앱의 알려진 Run 값만 대상으로 한다. 기존 값이 검증된 이 앱의 실행 명령일 때만 새 명령으로 갱신하고, 성공 확인 후 검증된 중복 항목만 제거한다.
- 자동 실행이 꺼져 있으면 이름 변경을 이유로 켜지 않는다. 알 수 없는 값이나 다른 프로그램 명령은 그대로 보존하고 사용자에게 복구 필요를 알린다.

## 8. 업데이트 알림과 간편 적용

2026-10-03 사용자가 업데이트 후 배포 시 기존 사용자에게 알리고 간편하게 업데이트할 수 있도록 명시적으로 추가 요청했다. 기존 배포본에는 확인 기능이 없으므로 이 기능이 포함된 `Mini-Monitor` 기준 버전을 한 번 수동 설치해야 하며, 그 이후 릴리스부터 알림·적용이 가능하다. 최초 수동 설치에서도 기존 사용자 데이터를 보존하며 이전 프로그램 폴더는 자동 삭제하지 않는다.

- 별도 서버 없이 승인된 `contentriumkorea/mini-monitor`의 GitHub stable Release를 사용한다. 초안·사전 릴리스는 제외하고 SemVer 호환 안정 버전을 비교한다. 문자열 사전순 비교는 금지한다.
- `pyproject.toml`, `__init__.__version__`, Release 메타데이터의 버전이 일치해야 한다. 다운그레이드나 동일 버전 재설치를 일반 업데이트로 제안하지 않는다.
- 앱 소유 업데이트 확인기가 시작 후와 이후 하루 간격으로 제한된 조회를 수행한다. 네트워크 오류는 조용히 실패하고 앱 실행·센서·로그인에 영향을 주지 않는다. 수동 `업데이트 확인`도 제공한다.
- 계정·하드웨어·사용량·사용자 식별자를 보내지 않는다. GitHub 조회 자체의 일반 네트워크 메타데이터 외에 분석·추적 수집은 하지 않는다.
- 새 버전은 크기가 고정된 설정창 알림 영역과 트레이 알림으로 안내한다. 중요한 조작을 밀어내거나 수치 카드에 광고처럼 표시하지 않는다. 같은 버전 알림을 반복하지 않으며 `나중에`를 제공한다.
- 사용자가 `업데이트 후 다시 시작`을 눌렀을 때만 다운로드·적용한다. 알림을 받았다는 이유로 실행 파일을 교체하거나 앱을 종료하지 않는다.
- Release에는 정확한 버전·채널·ZIP URL·크기·SHA-256·내부 파일 목록과 해시를 담은 정규화 메타데이터 및 Ed25519 분리 서명을 게시한다. 앱은 고정 공개키와 유지되는 암호 라이브러리로 검증한다.
- GitHub HTTPS와 같은 위치의 해시 파일만으로 진위를 보장한다고 주장하지 않는다. 서명 키가 준비되지 않은 릴리스는 알림·수동 다운로드만 제공하며 앱 내 실행 파일 교체를 활성화하지 않는다.
- 서명 개인키는 저장소·앱·ZIP에 포함하지 않는다. Release 게시 권한과 서명 권한을 구분하며 공개키는 기준 버전에 고정한다. 서명 검증 실패 시 우회 버튼 없이 적용을 거부한다.
- 다운로드 URL은 서명된 메타데이터와 승인 저장소의 릴리스 자산에 한정한다. 리다이렉트도 GitHub의 검증된 자산 호스트만 허용하며 크기·시간·압축 해제 총량·파일 수를 제한한다.
- ZIP은 절대 경로·상위 경로 탈출·중복 경로·심볼릭 링크·reparse point·예상 밖 루트/파일을 거부한다. 서명, ZIP 해시, 모든 파일 해시를 임시 영역에서 검증한 뒤에만 종료를 요청한다.
- onedir 교체는 실행 중 폴더 밖의 앱 전용 staging과 같은 설치 볼륨에서 수행한다. 번들 helper의 신뢰된 해시를 실행 전 재검증하며, 정확히 검증된 경로를 별도 인수로 전달하고 셸 명령 문자열로 조합하지 않는다.
- 기존 앱은 정상 종료 경로로 COM·센서·작업 스레드·계정 서비스와 mutex를 정리한다. helper는 원래 프로세스의 종료를 제한 시간 기다린다. 종료 실패·쓰기 권한 부족·파일 잠금이면 원본을 유지하고 중단하며 강제 종료·권한 상승은 하지 않는다.
- helper는 해시를 다시 확인하고 기존 설치 디렉터리를 동일 부모의 복구용 백업으로 이름 변경한 다음 검증된 새 트리를 원래 경로로 옮긴다. 두 번의 이름 변경과 상태 저널로 중간 실패를 복구하며 이를 단일 원자 트랜잭션으로 주장하지 않는다.
- 새 앱 시작 확인은 핵심 UI·필수 자산 초기화만 요구한다. USB 연결·Codex 로그인·외부 네트워크가 없어도 정상 확인할 수 있어야 한다.
- 새 앱이 시작 실패하거나 종료된 뒤 실패가 확인되면 기존 디렉터리로 복구한다. 확인 시간 초과에도 새 앱이 살아 있으면 정상 종료를 요청하고, 종료되지 않으면 백업·저널을 유지하여 복구 필요를 알린다. 실행 중 파일을 바꾸거나 프로세스를 강제 종료하지 않는다.
- 사용자 데이터 디렉터리, 격리 `codex-home`, DPAPI 자료, 로그, 별도 `--config` 파일은 교체·삭제 대상이 아니다. 설치 경로를 유지하여 사용자가 켠 자동 실행 경로도 유지한다.
- 사용자 지정 설정이 설치 트리 안에 있거나 기존 배포 목록에 없는 파일·사용자가 변경한 파일이 발견되면 자동 폴더 교체를 중단하고 보존 절차를 포함한 수동 업데이트를 안내한다. 임의 파일을 새 실행 폴더에 복사하거나 백업 정리 때 삭제하지 않는다.
- 복구용 백업은 최소 다음 정상 실행 확인까지 보존한다. 정리는 이 업데이트가 만든 검증된 경로에만 한정하고 임의 상위 폴더·사용자 백업은 건드리지 않는다. 중단된 업데이트 저널은 다음 실행에 복구 안내로 노출한다.
- 개발 소스 실행과 관리자가 잠근 설치 위치는 자동 교체하지 않고 공식 Release 수동 설치 안내를 제공한다. 업데이트 완료와 단순 다운로드 완료는 구분한다.

- 기존 공급자 소스·DLL·글꼴은 현재 라이선스에 따라 필요한 고지와 출처를 포함한다. 공식 Codex CLI는 별도 설치 의존성으로 문서화하며 인증 자료·CLI 바이너리를 배포 ZIP에 넣지 않는다.
- 현재 문서가 허용하는 로컬·오픈소스 앱 인증 범위로 한정한다. 이 설계를 상업용·호스팅 인증 서비스에 그대로 확장하지 않는다.
- 서명 검증용 새 의존성은 버전 잠금·환경 무결성 기대 목록·제3자 구성 목록·라이선스에 함께 반영한다. `.gitignore`만 믿지 않고 허용 목록을 대조하며 공개 문서의 비공개 증빙 링크와 이전 버전 테스트 수치도 제거하거나 최신 검증으로 교체한다.
- Windows onedir ZIP은 실행에 필요한 내부 폴더를 보존한다. 빌드 정보·SHA-256·대응 소스·검증 결과와 사용법을 함께 제공한다.
- 배포 앱에 유효한 코드 서명이 없으면 미서명 사실과 Windows 경고 가능성을 고지한다. 서명되지 않은 결과물을 서명된 앱으로 표현하지 않는다.
- 개별 납품 ZIP 이름만 `YYYY-MM-DD HH'mm Mini Monitor.zip` 형식을 따른다. 저장소·프로젝트·내부 파일·폴더·URL·Release 태그에는 이 접두사를 적용하지 않는다.

## 10. 수용 기준과 검증의 한계

- 두 네이티브 방향과 반전 방향에서 카드가 경계를 넘거나 겹치지 않고, 모든 제목이 18px 이상이며 주요 값·반크기 `%`의 고정 앵커와 밑면 정렬이 유지된다.
- 0·100·미상, 긴 모델명, VRAM 미지원·99% 사용, 전력 미지원, Codex 로그인 전·지연·창 누락 상태의 렌더를 확인한다. 글자/값의 바운딩 박스뿐 아니라 실제 100% 크기 이미지로 육안 검수한다.
- GPU 센서 테스트는 다중 GPU·가상 GPU·동일 어댑터 결합·MiB 변환·D3D 대체·공유 메모리 거부·센서 누락을 검증한다. 기존 VRAM 금지 테스트는 이번 승인 범위에 맞게 변경한다.
- Codex 모의 프로토콜 테스트는 초기화·로그인·취소·로그아웃·형식 오류·타임아웃·프로세스 종료·정규 버킷 선택·동적 창 길이·최장 창 우선·계정 전환 후 늦은 응답 폐기를 검증한다.
- 설정만 연 상태에서 로그인과 수동 갱신이 가능하고 USB 검색·센서 시작이 발생하지 않아야 한다. 반복 시작/중지에도 서비스·자식 프로세스는 하나이며 UI가 멈추지 않아야 한다.
- 별도 기본 Codex 홈은 읽거나 변경하지 않으며, 비밀이 설정·로그·진단·GitHub·ZIP에 포함되지 않아야 한다.
- 카드 불투명도 0·50·100%, 크기 변경, 드래그, 다중 모니터 위치 복원에서 전경 불투명·바깥 투명·항상 위 동작을 확인한다. 밝기·방향·자동 실행·단일 인스턴스 회귀 테스트를 통과한다.
- 기존 전체 테스트와 패키징 검증을 통과하고, 새 EXE의 콘솔 없는 GUI 시작 및 CLI 진단 시작을 확인한다. 테스트 통과만으로 실계정·실장치 동작을 검증했다고 주장하지 않는다.
- 업데이트 테스트는 버전 정렬, stable 선택, 서명·해시 변조, 악성 ZIP 경로, 오프라인, 반복 알림 억제, 사용자 취소, 잠금/쓰기 실패, 정상 종료 실패, 교체 중단, 시작 실패 복구, 살아 있는 새 프로세스의 확인 시간 초과를 검증한다.
- 두 실제 테스트용 onedir 버전으로 알림→사용자 적용→재시작을 확인하고 사용자 데이터·자동 실행 설정이 보존되는지 검사한다. 서명 없는 배포는 수동 다운로드로만 처리되는지 확인한다. 테스트용 릴리스를 운영 stable로 게시하지 않는다.
- 서명 키 운영과 두 버전 간 적용 검증이 준비되지 않았다면 간편 업데이트 구현 완료로 판정하지 않고, 알림·수동 다운로드만 검증한 상태라고 구분한다.
- 실로그인은 사용자가 브라우저 인증을 수행한 뒤 계정 한도와 화면의 일치 여부를 별도 확인한다. 실행할 수 없으면 그 한계를 Release 검증표에 명시한다.
- 실장치 검증은 허가된 장치와 포트에서만 진행한다. 이 설계 단계에는 어떤 COM 연결·전송도 포함하지 않는다.
- 공개 소스·Release URL·ZIP의 존재와 해시를 확인한 뒤 납품한다. 문서 작성 완료는 구현 완료나 배포 완료를 뜻하지 않는다.

## 11. 설계 근거와 현재 승인 상태

기존 `layout.py`, `renderer.py`, `setup.py`, 센서 수집 코드, 이름·자동 실행·패키징 코드 및 미리보기를 검토했다. 공식 [Codex app-server 문서](https://learn.chatgpt.com/docs/app-server)의 계정·로그인·한도 인터페이스를 기준으로 한다.

이 문서는 개념 승인을 구현 계약으로 구체화한 설계서다. 사용자는 설계·구현 계획과 병렬 실행 및 배포까지의 진행을 승인했다. 이 승인은 실계정 로그인·실장치 전송의 검증 완료를 뜻하지 않으며, 해당 검증 여부는 별도로 기록한다.
