# Mini Monitor Rust 전체 전환 설계안

## 목적과 선택

사용자가 선택한 방향은 설정창까지 포함하는 Rust 기반 Windows 앱으로 전체 전환이다. 기존 앱을 Python UI로 계속 유지하는 단계적 전환은 채택하지 않는다. 기존 사용자 기능과 설정을 유지하면서 작업표시줄 커서와 자원 사용 문제를 해결한다. 진단상 0.2.13 실행 프로세스의 메모리는 약 3 GiB이고, 짧은 관찰 기간에도 증가했다. 원인은 아직 확정되지 않았으므로 Rust 전환 자체를 원인 해결의 증거로 삼지 않는다.

## 범위와 호환성

- CPU·GPU·RAM·VRAM·Codex·OpenAI API 사용량을 기존 미니 USB 화면, PC 오버레이, 사용자 선택형 작업표시줄 바에 표시한다. API는 공식 Costs API, 설정한 총액 대비 시작일 기준 월별 집계를 유지한다.
- USB35INCHIPSV2의 VID/PID/일련번호 확인, 안전한 밝기 제한, 가로·세로·180도 반전, 연결·중지·재연결, 기존 검증된 직렬 프로토콜을 유지한다. 잘못된 장치에는 전송하지 않는다.
- 설정창, 트레이, 자동 시작, 상태창 투명도·위치, 작업표시줄 항목·스타일·드래그와 위치, 다중 모니터·배율·전체화면 동작을 보존한다. 텍스트는 배경 투명도에 영향을 받지 않는다.
- 기존 `%LOCALAPPDATA%/AI-Mini-Monitor`의 JSON 설정과 Codex 전용 로그인 영역, DPAPI 관리자 키 저장 형식·엔트로피를 호환한다. 기존 실제 인증정보의 값을 읽어 출력·복사하거나 새 계정을 만들지 않는다. 합성 키와 격리 데이터로 호환성을 검증한다.
- 기존 Ed25519 서명 업데이트와 온라인 설치기의 파일명·매니페스트·설치 경로를 유지한다. 기존 Python 패키지가 새 빌드를 업데이트할 수 있는지 실제 격리 업데이트 경로로 검증한다. 배포·설치 교체는 별도 요청 없이는 하지 않는다.

## 구조

Rust 단일 주 프로그램이 UI·Windows 창/트레이·센서 스케줄러·직렬 전송·렌더링·사용량 조회·설정 및 업데이트를 소유한다. 기존 Python 런타임은 최종 앱에 포함하지 않는다. 운영체제 API 및 필수 외부 구성요소(현재 Codex 인증 런타임 등)는 각각 보안·라이선스·배포 조건을 확인하고 최소화한다. GPU 온도·전력 등 기존 센서에서 제공되던 값은 지원 가능한 경로를 검증하고, 대안이 없으면 임의 값을 표시하지 않고 미지원으로 보고한다. 기술 선택은 성능 측정과 실제 장치 호환성을 기준으로 한다.

작업표시줄 창의 기본 커서를 명시하고, 창 메시지 처리·드래그·전체화면 전환이 상호작용을 막지 않는지 검증한다. 센서 수집과 화면 그리기는 독립된 제한 주기로 동작하고 실제 값이 바뀐 영역만 다시 그린다. 네트워크는 UI 스레드 밖에서 수행하며 실패 시 마지막 값의 최신 여부를 명확히 한다. 메모리·핸들·CPU를 장시간 측정해 증가 원인을 추적한다.

## 안전 및 검증

- 기존 소스와 설치본은 보존하고 별도 작업 영역과 합성 계정·설정·센서 데이터로 개발한다. 기존 설치본과 비밀정보를 자동 초기화하거나 삭제하지 않는다.
- 전환 전 기준선과 Rust 빌드를 같은 조건에서 비교한다. CPU는 코어 기준과 전체 시스템 기준을 명시하고, 메모리는 시작·안정·장시간 사용량과 증가 추세를 측정한다. 전후 수치가 없으면 개선을 주장하지 않는다.
- 단위·통합 테스트와 실제 Windows 창의 마우스 커서, 드래그, DPI, 트레이·시작 메뉴, 오버레이·작업표시줄 독립 동작을 검증한다. USB 실제 출력은 연결된 지원 기기가 확인될 때만 검증하고 미검증은 명시한다.
- 기존 Codex 로그인·OpenAI 관리자 키·설정 이전, 설치기와 업데이트 경로는 실제 사용자 비밀을 노출하지 않는 격리 fixture로 먼저 검증한다. 실제 계정 조회는 사용자 설정과 권한에 의존하며 별도로 검증 결과를 밝힌다.
- 성능 문제의 현재 원인은 확정 전으로 남긴다. 특정 라이브러리나 Python 자체를 원인으로 단정하지 않는다.
